# 首页下钻与信息层级记录

目标：点击之后继续展示可核对的数据，不生成结论文字，也不把只有提示框的图表伪装成下钻入口。

## 当前交互边界

| 入口 | 当前行为 | 数据关系 |
|---|---|---|
| 热门艺人、热门专辑 | 打开详情 | 对象 × 日期、曲目、最近播放、前后周期排名 |
| 客户端饼图与表格 | 打开客户端详情 | 客户端 × 日期、曲目、艺人/专辑、最近播放、前后周期排名 |
| 交叉分析中的艺人、专辑、客户端 | 打开同一对象详情 | 保留当前日期、时区、服务器、用户和指标范围 |
| 转码、小时、每日、周时热力图 | 只在悬停时显示原始数值 | 暂无点击动作，也不显示点击指针 |

“其他”聚合项和未知客户端不下钻，因为它们不是稳定、单一的对象。

## 后续下钻顺序

1. 转码状态：点击“直出/转码”后，展示该状态下的日期趋势、客户端构成和热门曲目。三组数据都能直接由 `is_transcoding` 过滤得到，且能回答这个状态由什么内容组成。
2. 周时单元格：点击某个“星期 × 小时”后，展示该时间单元内的客户端、艺人和曲目排行。查询必须按所选时区计算星期与小时，不能使用服务器本地时间替代。
3. 每日点位：点击日期后，展示当天的客户端、艺人和专辑构成。先使用局部详情，不静默改变首页的全局日期范围。
4. 小时柱：展示该小时在不同星期的分布，以及主要客户端；避免重复复制现有周时热力图。

每个入口都应复用当前全局筛选，并在 URL 中保留可分享的下钻身份。数据不足时只显示空状态，不补写推测。

## 首页内容层级

当前首页依次平铺正在播放、概览、客户端/转码、小时/每日、周时热力图、三张交叉图、排行、来源和历史记录。内容已经超过一次快速浏览所需，但暂不建议用传统分页：分页会拆散同一筛选范围下需要互相对照的图表，也会增加筛选状态同步成本。

更合适的后续结构是保留一套全局筛选，分成三个可直接定位的层级：

- 概览：正在播放、核心数字、每日趋势、艺人/专辑排行。
- 关系：客户端/转码、周时分布、交叉分析及其下钻。
- 记录：服务器来源与播放历史。

可以采用页内导航或有 URL 状态的视图切换；不根据系统生成的“洞察”自动折叠内容，也不默认隐藏数据。是否实施应在更多下钻完成后，再用首页长度、首屏可见内容和移动端滚动距离做一次实际比较。
